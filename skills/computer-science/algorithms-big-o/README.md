## Ordem de crescimento

```text
O(1) < O(log n) < O(n) < O(n log n) < O(n²)
```

## Objetivo de entrevista

Não basta dizer "é rápido". Explicar:
- tamanho da entrada;
- operações dominantes;
- pior caso quando relevante;
- memória adicional;
- trade-off tempo × espaço.

## Padrões prioritários

- linear scan
- hashing/frequency counter
- two pointers
- binary search
- sorting
- sliding window básico

## Frase útil

> A solução inicial é O(n²) porque para cada elemento faço uma segunda busca. Posso usar um Map para fazer lookup médio O(1), reduzindo o tempo total para O(n), ao custo de O(n) de memória adicional.
