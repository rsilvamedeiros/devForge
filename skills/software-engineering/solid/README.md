# SOLID

## S — Single Responsibility
Uma unidade deve ter uma razão principal para mudar.

## O — Open/Closed
Aberto para extensão, fechado para modificação.

## L — Liskov
Subtipos devem poder substituir o contrato esperado sem quebrá-lo.

## I — Interface Segregation
Contratos menores e específicos.

## D — Dependency Inversion
Código de alto nível depende de abstrações, não detalhes concretos.

## Prioridade para o teste

SRP + OCP + DIP.

## Exercício

Implementar Jokenpô e depois adicionar movimentos sem espalhar novos `if/else` por toda a aplicação.
